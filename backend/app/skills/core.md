# seyo 앱 만들기: 기본 스킬

학생용 아이패드 플래너 seyo의 페이지 한 장 안에서 돌아가는 HTML 파일 하나를 만든다. 무엇을 만들지는 자유다. 아래는 어떤 앱이든 지키는 바닥선이다.

## 실행 환경 (어기면 동작하지 않는다)
- 화면 폭 360~1000px, 높이는 페이지 카드 크기. 손가락과 애플펜슬로 누른다. hover에 기대지 않는다.
- 인터넷이 막혀 있다. 외부 스크립트, CDN, 라이브러리, 웹폰트, 외부 이미지, fetch 모두 쓸 수 없다. 그림은 인라인 SVG나 CSS로 그린다.
- 사진은 된다 (사용자 기기의 사진, 이미 작게 줄인 JPEG data URL로 받는다).
  - 고르기: 버튼 클릭 핸들러 안에서 `seyo.photo().then(url => { S.photos.push(url); save(); render(); })`. 썸네일만 필요하면 `seyo.photo({ max: 600 })`.
  - 붙여넣기·끌어다 놓기: `seyo.onPhotoPaste(url => { ... })`를 시작할 때 한 번 등록한다. 사진을 받는 칸이 있으면 고르기 버튼과 붙여넣기를 둘 다 연결하고, 빈 칸에 "사진을 고르거나 붙여넣어요"라고 적는다.
  - 받은 url은 seyo.state에 저장하고 `<img src="...">`로 보여준다 (`object-fit: cover`, 둥근 모서리). 지우기 버튼도 둔다. 사진은 한 장에 수십~수백 KB라 한 페이지에 수십 장 이하로.
- alert, confirm, prompt는 막혀 있다. 확인이 필요하면 화면 안에 작은 확인 줄을 그린다.
- 데이터 저장
  - 열릴 때 `window.seyo.state`에 지난번 저장한 객체가 있다 (처음엔 `{}`). 항상 기본값과 합쳐서 읽는다: `const S = Object.assign({ items: [] }, seyo.state);`
  - 바뀔 때마다 `seyo.save(S)`를 부른다. 저장하지 않으면 페이지를 닫을 때 다 사라진다.
  - 저장 데이터에 함수, Date 객체, DOM을 넣지 않는다. 날짜는 `"2026-11-19"` 문자열이나 ms 숫자로.
- 홈 위젯 숫자: `seyo.widget('라벨', 값)`. 앱의 핵심 숫자(남은 일, 연속 일수, 레벨 등)가 바뀔 때마다 부른다.
- 오늘 날짜는 `new Date()`. 로컬 날짜 키는 `d.getFullYear()+'-'+(d.getMonth()+1)+'-'+d.getDate()` 식으로 만든다 (toISOString은 UTC라 하루가 밀린다).

## 첨부 사진 (요청에 사진이 같이 오면)
- 기본: **무드만 참고한다.** 레이아웃, 구조, 키트 컴포넌트, 간격, 글자 위계는 언제나 seyo 기준 그대로다. 사진의 배치를 따라 하지 않는다.
  1. 먼저 HTML 맨 앞(요약 주석 다음)에 `<!-- 무드: ... -->`로 읽은 것을 적는다: 가장 가까운 테마 하나, 주요 색 2~3개(hex), 장식 느낌(테이프·스티커·리본·체크·빈티지 등).
  2. 그 테마를 `<body class="theme-...">`로 고르고, 사진 색에 맞춰 `--accent`, `--accent-soft`, `--bg`만 조정한다. 장식은 style 스킬의 재료(.tape .sticker .stamp, 작은 SVG)로 그 느낌을 낸다.
  3. 사진 속 글자, 로고, 상표, 캐릭터, 내용은 베끼지 않는다. 홍보 이미지(기기 목업, 배지, 광고 문구)도 무드만 본다.
- 요청 문장이 사진을 어떻게 쓰라고 말하면 그 말대로 한다. 예: "이 사진 배경으로" → 배경 이미지, "이 표 내용 옮겨줘" → 사진 속 내용을 데이터로, "로고로 넣어줘" → 그 자리에 이미지. 이때도 나머지 구조는 seyo 기준.
- 사진 자체를 페이지에 넣는 건 요청이 그렇게 말할 때만이다 (그때 사용자 메시지에 `{{photo1}}` 사용법이 따로 온다). src에 `{{photo1}}`, `{{photo2}}`… 를 그대로 쓰면 서버가 실제 사진으로 바꾼다. base64를 직접 쓰지 않는다.
- 코드 안의 `data:seyo/0` 같은 값은 이미 들어간 사진이다. 그대로 둔다.

## 디자인 원칙 (seyo 감성)
- seyo는 "딱 맞는 페이지가 없으면, 그냥 말하면 생기는" 나만의 페이지다. 사용자는 노션·다이어리를 꾸미는 대학생과 작은 팀.
- 기본 감성은 애플 + 노션: 미니멀하고 세련되게. 흰 바탕이나 테마 면, 넉넉한 여백, 얇은 선, 가는 큰 숫자, 둥근 알약 버튼, 회색 위계의 글자. 포인트는 아기 분홍·아기 하늘 면으로만 조금. 분홍·하늘 위 글자는 `--ink`.
- 기능을 늘리지 말고 요청에 꼭 필요한 것만. 화면에 요소가 적을수록 좋다. 설명 문구, 장식 카드, 통계 칸을 습관처럼 붙이지 않는다.
- 금지(기본값일 때): 쨍한 원색, 진한 그림자, 두꺼운 테두리, 무지개 그라데이션, 이모지 도배, 카드 안의 카드 안의 카드.
- **사용자가 말(글)로 디자인을 분명히 말하면 그게 우선이다.** (첨부 사진은 무드만, 위 '첨부 사진' 참고) 색("검정 배경", "보라색"), 분위기("귀엽게", "레트로", "다꾸 느낌", "iOS Core로", "게임처럼"), 글자 크기, 배치를 말하면 위 기본 감성보다 그 말을 따른다. 키트 변수(`:root{--accent:..;--card:..}`)와 직접 CSS로 확실히 바꾼다. 말하지 않은 부분은 seyo 기본을 유지한다.
- "iOS Core", "애플처럼"은 iOS 기본 앱 느낌: 회색 그룹 배경 위 흰 둥근 목록, 시스템 파란 강조(#0a84ff), 큰 굵은 제목.

## 디자인 키트 (이미 들어 있다, 따로 정의하지 말고 클래스만 쓴다)
모든 앱에 seyo 디자인 키트 CSS가 자동으로 들어간다. 기본 태그(body, h1~h3, p, button, input, textarea, select)는 이미 예쁘게 잡혀 있다.
- 색 변수: `--ink`(글자) `--sub`(보조 글자) `--faint` `--line`(선) `--fill`(옅은 회색 면) `--card`(흰 카드) `--pink` `--pink-soft` `--blue` `--blue-soft`(포인트 면) `--accent`(진분홍, 체크·진행바 같은 작은 표시) `--accent-2`(진하늘) `--good`(초록) `--bad`(빨강). 다른 색이 필요하면 `:root{--accent:#...}`만 덮어쓴다.
- 레이아웃: `.app`(바깥 틀, 여백과 최대 폭) `.stack`(세로 간격) `.row`(가로, 가운데 정렬) `.between`(양끝 정렬) `.grid`(자동 칸) `.wrap`
- 면: `.card`(흰 카드) `.soft`(옅은 회색 면) `.tint-pink` `.tint-blue`(`.soft`/`.card`에 더하면 분홍·하늘 면) `.hero`(큰 숫자 영역)
- 글자: `.title`(화면 제목) `.label`(작은 회색 글) `.big`(큰 숫자) `.muted`
- 버튼: `button`(기본, 옅은 회색 면) `.primary`(검정, 화면의 주 버튼 하나) `.btn-accent`(분홍 면) `.btn-blue`(하늘 면) `.btn-ghost`(검정 테두리) `.icon-btn`(동그란 44px) `.chip`(작은 알약, `.on`이면 분홍으로 선택, `.blue`는 하늘 태그)
- 버튼 배경을 직접 바꾸면 글자색(color)도 반드시 같이 지정한다. 달력 칸, 카드처럼 버튼이 아닌 모양이면 `<div>`에 클릭을 단다.
- 입력: `input`, `textarea`, `select`는 그대로 쓴다. `.field`(라벨 + 입력 묶음)
- 목록: `.list` 안에 `.item` (체크 항목은 `.item.done`이면 흐려진다), `.check`(동그란 체크 버튼)
- 진행: `<div class="bar"><i style="width:40%"></i></div>`, `.ring`은 SVG로 직접.
- **스타일 테마** (`<body class="theme-...">` 한 줄이면 색·배경·모서리가 바뀐다): `theme-pastel`(파스텔 다꾸) `theme-kitsch`(키치·Y2K, 체크 배경, 검은 테두리 스티커 카드) `theme-ribbon`(리본·발레, 세리프 제목) `theme-retro`(빈티지 크라프트지) `theme-notion`(노션 미니멀) `theme-ios`(iOS 기본 앱) `theme-dark` `theme-grid`(모눈 노트). 테마 없이 두면 seyo 기본.
- **다꾸 재료**: `.paper-dot` `.paper-grid` `.paper-line`(종이 질감, 카드나 영역에) `.tape`(마스킹테이프, 카드 안 맨 앞에 `<i class="tape pink"></i>`, `.blue .yellow .mint .check`, 위치 `.left .right`) `.sticker`(오린 스티커) `.polaroid`(사진 틀, 안에 `<img>`나 `<div class="ph">`) `.stamp`(날짜 도장) `.mark`(형광펜 밑줄) `.tilt-l .tilt-r`(살짝 기울이기) `.title-serif` `.mono`
- 키트 클래스(`.cal .week .grid .row`)의 배치·열 수를 덮어쓰는 CSS나 미디어쿼리를 따로 쓰지 않는다. 반응형은 키트가 맡는다.
- **플래너 틀**: `.cal`(7칸 달력: `.cal` 안에 **바로** 요일 7개 `.cal-dow`와 날짜 칸 `.cal-cell`(+ `.today .out .sun`)을 형제로 넣는다. 감싸는 div 없이. 1일 앞 빈칸은 `.cal-cell.out`) `.week`(7일 위클리, 칸은 `.day-col`, 좁으면 2열로) `.cover`(노션식 커버 띠) `.callout`(아이콘+한 줄 강조) `.tabs`(알약 탭, 버튼에 `.on`)
- 작은 표시: `.badge`(둥근 알약 라벨, `.pink` `.blue`). 숫자나 상태를 작게 붙일 땐 배경만 칠한 네모 span 말고 이걸 쓴다. 배경색이 있는 요소는 모두 둥글게(`border-radius`).
- 빈 화면: `.empty`(가운데 회색 안내)
- 움직임: `.pop`(톡 튀어나옴) `.fade`(서서히) `.shake`. 직접 만든 애니메이션은 0.15~0.4초.

## 화면 짜기
- 첫 화면에서 바로 쓸 수 있어야 한다. 위에서 아래로: 제목 한 줄 → 핵심 숫자나 상태 → 입력/조작 → 목록이나 기록.
- 처음 열었을 때 빈 상태도 보기 좋게: `.empty`로 무엇을 하면 되는지 한 줄.
- 누르는 것은 최소 44px. 중요한 버튼은 하나만 눈에 띄게.
- 날짜 기본값은 오늘이 아니라 그럴듯한 미래 날짜로 (수능은 11월 셋째 목요일, 중간고사는 한 달 뒤 등), 그리고 화면에서 바꿀 수 있게. 기본 날짜가 올해 이미 지났으면 내년 날짜로 계산한다. 디데이는 남으면 `D-12`, 당일 `D-DAY`, 지나면 `D+3`으로 쓴다 (`D--3` 금지).
- 큰 숫자 여러 개를 나란히 둘 땐 `.grid`나 `.between`으로 칸을 나누고 각 숫자 위에 `.label`을 붙인다. 숫자끼리 붙어 하나로 읽히면 안 된다.
- 요일은 월~일 7칸을 한 번씩, 순서대로. 오늘 기준으로 밀지 않는다.
- 문구는 짧은 한국어 해요체 ("기록했어요", "오늘 3개 남았어요"). 영어 UI 문구(버튼, 칩, 상점 아이템 이름 포함), Lorem, 가짜 예시 데이터 금지. 이모지는 꼭 필요할 때 한두 개만.
- 누르면 반드시 눈에 보이는 반응이 있다 (숫자 변화, 체크, 짧은 애니메이션).
- 지우기는 실수 방지: 한 번 누르면 "한 번 더 누르면 지워요"로 바뀌는 식.

## 코드 짜기
- `<style>`은 `<head>`, `<script>`는 `</body>` 바로 앞. 스크립트 하나에 상태(S) → `render()` → 이벤트 순서.
- 상태가 바뀌면 `save(); render();`. render는 화면을 상태에서 다시 그린다 (innerHTML 써도 된다, 사용자 글은 escape).
- 사용자가 입력한 글을 innerHTML에 넣을 땐 반드시 escape 함수를 거친다.
- 스크립트가 만지는 요소에는 그 요소 자체에 id를 붙이고 `document.getElementById('id')`로 찾는다. `#bar i` 같은 자손 선택자로 찾지 않는다 (마크업과 어긋나면 null 오류로 화면이 멈춘다).
- render()는 한 요소가 없어도 나머지는 그려지게, 찾은 요소가 null이면 건너뛴다.
- 타이머나 시간 계산은 `Date.now()` 차이로. setInterval 횟수를 세지 않는다.
- 300줄 안쪽으로 간결하게. 쓰지 않는 코드, 주석 덩어리 금지.

## 내보내기 전 점검
- [ ] 외부 주소(http, //cdn) 없음, alert/confirm/prompt 없음
- [ ] 데이터가 바뀌는 모든 곳에서 seyo.save
- [ ] 처음 열었을 때(빈 state) 오류 없이 보임
- [ ] 360px 폭에서도 가로로 넘치지 않음
- [ ] 문구가 모두 한국어 해요체
